# ネットワーク設計支援資産

更新日: 2026-10-02。
構成資料はドラフト。社内規程の承認、M365への登録、ファイル生成・保存の実動作確認は別途必要です。

## 使い始める順序
1. `04_Prompts/Agent/設計支援エージェント.md` をエージェントの指示欄へ反映する。
2. `04_Prompts/Agent/M365適用手順.md` に従い、必要な資料を知識へ登録する。フォルダを置くだけで設定が実行されるとは扱わない。
3. `01_Governance/02_生成標準/Common/工程定義.yaml` を工程の基準とし、共通モデルから全成果物を生成する。
4. `05_Knowledge/03_KnowledgeIndex/資産台帳.json` で資料の所在と利用制限を確認する。存在は承認を意味しない。
5. `04_Prompts/Review/受入テスト.json` の架空ケースで確認してから実案件へ適用する。

## 正本と用途
- 案件の事実: 入力資料・確認記録。要件IDは案件ごとに採番する。
- 共通データ: Common/設計モデル.schema.json。Word・Excel・構成図・Config間で同じIDと値を使う。
- 工程と品質: Common/工程定義.yaml、検証ルール.json、成果物対応表.json。
- 文書書式: 人が適合性を確認した既存雛形。新v1.0の5種類は未承認ドラフト用。旧Word v3.0は要整備。
- 製品仕様: 対象型式・OS版に合う公式資料。サンプルの値は案件へ流用しない。
- 作業中: 06_Generated。承認済み成果物: 03_Deliverables。両方を一般の参考知識へ混ぜない。

## IDと修正範囲
Q-001等は質問ID、FIELD-001等は項目定義ID、REQ-案件ID-0001等は案件要件IDです。
既存資料の旧REQ番号は `02_DesignAssets/Requirements/02_Definition/項目対応表.json` で元ファイルと合わせて解釈します。
Excel集計は現在の質問72件・チェック22件を対象とします。行を追加したら集計範囲も更新してください。
新規Office雛形5種類は雛形対応表.jsonで管理しています。空の規程や空の対応機種表は承認済みとして扱いません。

## ローカル検証とM365指示
このフォルダは社内SharePointへの配置前の検証用コピーです。
指示欄は04_Prompts/Agent/M365指示欄_貼付用.txt、会話の依頼はM365依頼文集.md、検索用資料は05_Knowledge/04_RAG配布を使用します。
M365参照検証.jsonの実績は社内環境で取得するまでnot_runです。
